# What Is RealTimeX

RealTimeX is the AI work operating system for teams that need more than chat.

It brings together workspace chat, retrieval, meeting capture, agent runtimes, browser and MCP tooling, channels, plugins, and deployment choice so teams can move from context to execution in one product surface.

You can run it with hosted providers, self-hosted services, or on-device local models. You can also decide how much control you want over approvals, working directories, credentials, automations, and deployment shape.

## RealTimeX in one sentence

RealTimeX helps teams keep knowledge, action, oversight, and deployment strategy in one place instead of stitching them together across separate chat apps, automation tools, meeting products, and runtime wrappers.

## What makes RealTimeX different

### One surface from context to execution

RealTimeX is not only a prompt box. It lets teams:

- ask questions in workspace chat
- retrieve context from documents, notes, and knowledge collections
- run agent sessions and runtime-backed workflows
- connect meetings, calendar context, and follow-up
- expose AI through channels, plugins, and external integrations

### Multiple agent runtimes, not one narrow model path

RealTimeX can launch CLI-backed agent runtimes such as `Claude Code`, `Codex CLI`, `Cursor Agent`, `Antigravity CLI`, `Gemini CLI`, `Qwen Code`, and `OpenCode` from one governed product surface.

Depending on the runtime, RealTimeX can use the runtime's own login state or inject provider credentials at launch through [Agent Authentication](/agent-authentication). It does not force every agent through one API-only pattern.

### Operator control and governance

RealTimeX is built for teams that need more than a raw model response. Use [Workspaces](/workspaces), [Credentials](/credentials), [Users](/users), [Security](/security), [Agent Runtime](/agent-runtime), and [Channels](/channels) to control what AI can access, where it runs, and who can use it.

### Desktop, cloud, or hybrid rollout

RealTimeX supports multiple adoption paths:

- start on Desktop for a fast operator-led pilot
- move to Cloud for shared workspaces and centralized administration
- keep a hybrid setup when some execution or models should stay local

See [Desktop Overview](/installation-desktop/overview), [RealTimeX Cloud](/cloud/overview), and [Why RealTimeX](/why-realtimex).

## Who RealTimeX is for

RealTimeX is strongest when the work is repeatable, operational, and connected to real context. Common fits include:

- customer success and account teams
- operations and internal enablement
- support and service desks
- AI rollout and transformation programs
- teams that need runtime tools, local apps, MCP, or browser-backed execution

## Product roots

RealTimeX started from strong open-source roots and has expanded into a broader product with additional runtime, automation, and operator-control layers maintained by the RealTimeX team.
