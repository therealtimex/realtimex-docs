# Desktop Installation Overview

RealTimeX Desktop is often the fastest way to prove RealTimeX in a real workflow.

It is especially strong when one operator or a small team wants to connect local files, local models, CLI-backed agents, browser sessions, or local apps without waiting for a larger infrastructure rollout.

## Why buyers start with Desktop

- Fast pilot path: install the app and work with real context quickly.
- Strong local story: local files, local models, and local runtimes can stay on the machine.
- Operator-led rollout: one person can configure agents, credentials, plugins, and runtime behavior before widening access.
- Expand later: many teams start here, then move to Cloud or a hybrid setup after the workflow is proven.

---

## Desktop vs Cloud: choose the adoption path, not your forever architecture

RealTimeX is available in two main versions, each designed for different needs. Here’s a quick comparison to help you choose:

### You’ll love **RealTimeX Desktop** if:

- You want the fastest path to a real operator-led pilot
- You need local files, local models, or machine-local runtimes
- You do not need shared multi-user access yet
- You want to prove one workflow before broadening the rollout

### Choose **RealTimeX Cloud** if:

- You need shared workspaces for a team
- You want centralized administration and managed infrastructure
- You want to support multiple users at once
- You need channels, public exposure, or browser-based access
- You are rolling RealTimeX out as a broader operational system
